# 実装横断レビュー 2026-09-28

## 1 結論

Phase 1の契約・合成データ・静的UIは相互に整合しているが、本番導入可能な状態ではない。会社承認前という前提どおり、実データ、職場Google Drive、GAS、Cloudflareへの接続は行っていない。次の実装担当者は、下記P0を「済んでいる」と誤認してはならない。

## 3 今回強化した事項

- 仕様書9.1との衝突を明示したパスワード認証変更案と、平文列を許さない契約を追加した。
- 分析を自動指導提案から分離し、分布、比較可能人数、難易度差、時系列、設問結果、判定遷移、データ品質を判断材料として追加した。
- 分析レスポンスがscalarだけでなくdistribution、series、breakdown、matrixを表現できるようにした。
- 小人数抑制時に四分位・点列を返す漏えいも契約検証で拒否するようにした。
- ログイン画面は資格情報を送信・保存せず、合成表示の範囲に限定した。
- 河合塾実帳票をリポジトリ外・メモリ内で確認し、論理ページ判定、別人混在拒否、ページ1の科目成績14行、ページ2の9科目・分野別50行を抽出した。未構造化項目が残る間は登録不可とした。

## 4 導入判定ゲート

1. 会社が保存境界、SPEC-CHANGE-001〜005、Cloudflare保持条件、端末運用を承認する。
2. 実帳票をリポジトリ外で検証し、全取得項目・欠損理由・未知版拒否のゴールデン試験を通す。
3. GAS/Sheets結合試験で保存後完全復元、ハッシュ、競合、重複、訂正、年度分割、バックアップを通す。
4. 認証・権限・セッション・HMAC・CSRF・レート制限・ログ非漏えいを第三者レビューする。
5. 分析値を原票の手計算サンプルと照合し、母数・除外・抑制・版条件が一致する。
6. INPUT端末とADMIN端末で受入試験し、操作手順、障害時手順、退職者失効手順を承認する。

## 5 実装担当者への順序材料

本書は担当割当を決めない。安全な依存順は「会社判断が必要な仕様差分の確定 → 実帳票Parser → Sheets正本アダプタ → 認証・セッション → 集計エンジン → API接続UI → 結合・負荷・運用試験」である。Parserと認証の技術検証は並行可能だが、実データや本番アカウントへの接続は承認後に限る。

## 2 契約変更

帳票の情報損失を防ぐため、DomainResultItemへ次を追加した。

- `questionNumberRaw`: 設問番号の原表記
- `sameAbilityDifference`: 同学力帯平均との差
- `nextLevelDifference`: 一段階上判定者平均との差

JSON Schemaと実行時検証は完全列集合を要求し、欠落・未知列を拒否する。得点率差は帳票のパーセントポイント表記を数値のまま保持する。

## 3 抽出

- 横長ページを左右ブロックへ分離する。
- 科目見出しを検出し、設問行を所属科目へ関連付ける。
- 設問番号、分野名、得点・配点、全国・校内・同学力帯平均、平均との差、得点率差、最良・最低記号、一段階上判定者平均・差を保持する。
- 科目未受験行を0点へ変換しない。
- 添付実帳票で9科目、50行が既存試作の件数と一致した。

## 4 講評抽出

科目ブロック内の複数行講評は、レーダー凡例・学力レベル欄より下、次科目見出しより上の中央領域から抽出し、印字改行を`\n`で保存する。講評は設問ごとに複製せず、科目payload直下の`commentaryRaw`へ1回だけ格納する。実帳票では数値行のある全9科目で講評を抽出できることを、本文を表示・保存せず件数と改行数だけで確認した。

## 5 受入条件

- 左右ブロックの最終差列を隣ブロックへ誤所属させない。
- DomainPayloadの全項目が契約検証を通る。
- 分野行0件をFATALとして拒否する。
- ページ1、3、4の未構造化項目が残る間は`READY`にならない。

# 個人情報の保存境界

## 1 基本方針

個人情報を永続保存できる場所は、職場PC Googleアカウントが所有するGoogle Drive上の非共有Google Sheetsだけとする。バックアップも同アカウントのGoogle Drive内に作成する。

システムの機能を維持するため、ブラウザ、Cloudflare Functions、GASの実行メモリ内で一時的に処理することは許容する。ただし、処理終了後に再取得可能な形で保存してはならない。

## 2 データ分類

| 区分 | 例 | 扱い |
|---|---|---|
| 直接識別子 | 氏名、メール、学校、クラス、番号 | 個人情報 |
| 成績情報 | 得点、偏差値、順位、正誤、志望校 | 個人情報 |
| 仮名化情報 | StudentID、ML_ID | 対応可能性がある限り個人情報として扱う |
| 認証情報 | OTP、セッションID、HMAC secret | 機密情報 |
| PDF本体 | 模試個人成績表 | 個人情報を含む機密ファイル |
| 集計情報 | 十分な人数の平均・分布 | 再識別リスクを評価して扱う |
| 合成データ | 架空氏名・架空成績 | GitHubテスト資産として利用可能 |

## 3 許可する永続保存先

| 保存先 | 許可 | 条件 |
|---|---|---|
| 成績データGoogle Sheets | 可 | 職場PCアカウント所有、原則非共有 |
| システム台帳Google Sheets | 可 | 職場PCアカウント所有、一般利用者へ非共有 |
| 権限管理Google Sheets | 可 | 制限付き共有、権限管理社員だけ編集 |
| Google Drive Backupフォルダ | 可 | 職場PCアカウント所有、原則非共有 |
| Script Properties | Secretのみ可 | 個人の成績・氏名を保存しない |
| CacheService | 非個人情報のみ条件付き | replay防止nonce等。利用者、OTP、セッション、成績を保存しない |

## 4 禁止する永続保存先

- GitHubのコード、Issue、Pull Request、Actionsログ、Artifact
- Cloudflare KV、D1、R2、Durable Objects、Queues、Cache
- Cloudflareのアプリケーションログ、console.log、第三者ログ転送
- ブラウザlocalStorage、sessionStorage、IndexedDB、Cache API
- Service WorkerによるAPI応答キャッシュ
- 外部エラー監視・アクセス解析サービスのイベント本文
- 開発者個人のGoogle Drive、Dropbox等
- 開発PCのテストデータ、スクリーンショット、エクスポート
- メール、チャット、IssueへのPDF添付
- GitHubへ置く仕様書本体や実データ由来の画像

## 5 コンポーネント別境界

### 5.1 利用者ブラウザ

- 利用者が選択したPDFをArrayBufferとしてメモリ内で解析する。
- PDF本体と抽出全文をネットワーク送信しない。
- 抽出結果は確認画面の表示中だけ保持する。
- ページ再読込、登録完了、明示クリアで参照を破棄する。
- オートコンプリート、フォーム復元、ブラウザキャッシュの対象にしない。
- 識別可能なCSVやExcelを自動ダウンロードしない。

入力PDFそのものは利用者PC上に存在するため、システムは追加コピーを作らない。登録後の原本削除・保管は会社の端末運用規程として別途定める。

### 5.2 Cloudflare Pages

- 静的コードと固定バージョンの依存ファイルだけを配信する。
- 個人情報を含む静的ファイルを置かない。
- 外部解析タグを設置しない。

### 5.3 Cloudflare Functions

- 認証、署名付与、GASへの中継を実行メモリ内で行う。
- リクエスト本文とレスポンス本文をログへ出さない。
- Cache-Controlをno-storeとする。
- KV、D1、R2等へ保存しない。
- エラー応答へ入力値を埋め込まない。
- プラットフォーム側の運用ログ・保持条件は本番承認前に確認する。

### 5.4 Google Apps Script

- セッション、権限、入力、重複、保存先を再検証する。
- 永続成績はGoogle Sheetsへ保存する。
- OTP Challengeとセッション状態は、個人情報保存境界を守るため、職場PCアカウント所有の非共有Google Sheetsへ有効期限付きで保存する案を初期方針とする。
- CacheServiceは利用者と結び付かないreplay防止nonce等に限定する。
- 監査ログは必要最小限とし、OTP、セッションID、Secret、PDF本文を含めない。
- Script Propertiesへ個人情報を保存しない。

### 5.5 Google DriveとGoogle Sheets

- 職場PC Googleアカウントを所有主体とする。
- 成績データとシステム台帳は一般利用者へ直接共有しない。
- 権限管理スプシは制限付き共有とする。
- 保存先IDをクライアントから受け取らない。
- 年度・容量に応じてGASが保存先を決定する。

### 5.6 GitHub

- コード、非機密設計文書、合成データだけを置く。
- 実PDF、実スプレッドシート、実CSV、実氏名、学校コード、受験番号を置かない。
- テストは合成または十分に匿名化され再識別できないデータだけを使用する。
- 匿名化の判断が曖昧なデータはGitHubへ置かない。

## 6 API通信

API本文はHTTPSで送信する。JSONは通信形式として使用できるが、Cloudflareやブラウザ永続領域へ保存しない。GASが受信後に正規化・検証し、Google Sheetsの列へ保存する。JSON文字列を成績の正本としてセルに保存する設計は、仕様変更承認なしに採用しない。

## 7 エクスポート

- 直接識別子を含むエクスポートは初期版で禁止する。
- 分析画面はブラウザ表示を基本とする。
- ML用出力は氏名・メール等を除外し、仮名化しても個人情報として扱う。
- 初期案ではML用データを職場PCアカウント所有の専用Google Sheetとして生成し、CSV自動ダウンロードを行わない。
- ML用ファイルをGoogle Sheets外へ保存する機能は、会社承認と別の保存・処理境界が確定するまで有効化しない。
- 将来有効化する場合も、出力者、目的、項目、期間、保存先、削除期限を監査する。

## 8 ログ

許可する例:

- Timestamp
- RequestID
- Google Sheets上の監査ログに限るActorEmailまたはActorIDの必要最小限の識別子
- Action
- Result
- 対象年度、RecordID等の最小情報
- AppVersion、ParserVersion
- 個人情報を含まないエラーコード

禁止する例:

- Cloudflare、ブラウザconsole、外部監視等のアプリケーションログに含まれる氏名、メール、学校名、クラス、番号
- 得点、偏差値、順位、志望校
- PDF本文、抽出全文、API本文
- OTP、セッションID、Cookie、HMAC secret
- スプレッドシートの内容全体

## 9 インシデント初動

1. 追加書込、デプロイ、公開を停止する。
2. 流出先、期間、対象データ、アクセス可能者を確認する。
3. Secretが含まれる場合はローテーションする。
4. GitHub履歴等に入った場合は単純削除で完了とせず履歴除去を行う。
5. 会社の報告経路へ連絡する。
6. 原因、影響、再発防止、検証結果を記録する。

## 10 受入確認

- [ ] 永続保存先がGoogle Drive上の所定Sheetsだけである
- [ ] GitHubに実データがない
- [ ] Cloudflareストレージを使用していない
- [ ] ブラウザ永続領域を使用していない
- [ ] ログへ禁止情報を出力していない
- [ ] 識別可能なファイルを自動ダウンロードしない
- [ ] ML出力が未承認状態で無効化されている
- [ ] OTP・セッションの利用者情報がCacheServiceへ保存されていない
- [ ] 本番承認前にCloudflareのデータ保持条件を確認する項目が残っている

# 分析要件カタログ

## 1 方針

分析タブは「数字を多く出すこと」ではなく、塾講師・社員が生徒・集団の状態を正確に捉え、自ら指導判断を行うための材料を揃えることを目的とする。システムは指導対象・指導内容・原因を断定せず、観測値、比較、分布、推移、母数、欠損、データ品質を提示する。初期対応は河合塾・全統共通テスト模試とするが、分析定義は提供元固有の列名へ直接依存させない。

分析画面はADMIN以上だけが利用できる。INPUTには分析APIも過去データも返さない。氏名等の直接識別子は個人詳細で必要なときだけ扱い、集団分析では返さない。

## 2 共通フィルタ

| 区分 | フィルタ | 備考 |
|---|---|---|
| 模試 | 提供元、模試種別、年度、回次、実施日、帳票スキーム、指標定義 | 第何回とMetricDefinitionIDを独立キーにする |
| 組織 | 登録校舎、複数校舎、全校舎 | 校舎はアップロード時に選択した値 |
| 生徒属性 | 高校、学校コード、学年、卒業見込年度 | クラス・校内番号は分析軸の既定値にしない |
| 科目 | 教科、科目、科目グループ、受験型 | 未受験者を母数へ含めるか表示する |
| 志望 | 大学、学部、学科・方式、志望順位、判定 | 名称表記揺れ用の正規化IDを持つ |
| データ品質 | ParserVersion、SchemaVersion、警告有無、欠損理由 | 管理用フィルタ |

比較対象は基準群と比較群を明示する。例えば「札幌校舎 対 全校舎」「高校A 対 同学年全体」のように、母数と除外条件を常に表示する。

### 2.1 分析表示の原則

1. 事実と解釈を分離し、画面には観測値と比較根拠を表示する。
2. 平均だけでなく中央値、四分位、分布、人数を併記する。
3. 変化量には、比較できた同一Person数と比較不能数を付ける。
4. 得点変化と全国平均との差の変化を並べ、問題難度変化の影響を見分けられるようにする。
5. 科目から分野、大問、設問、解答状態へ段階的に掘り下げられるようにする。
6. 「無解答が終盤に多い」等は観測事実として示し、「時間不足」等の原因は断定しない。
7. 帳票掲載値とシステム内集計値を別の名称・色・凡例で表示する。
8. 小人数抑制、欠損、SchemaVersion不一致を値の不存在と混同させない。

### 4.9 ドリルダウン階層

画面は `全体 → 校舎・高校 → 科目 → 分野 → 大問 → 設問 → 個人` の順で絞り込めるようにする。各階層で次を保持する。

- 現在の対象条件と比較基準。
- 対象人数、比較可能人数、除外人数、MissingReason内訳。
- ExamEventID、MetricDefinitionID、SchemaVersionID、集計定義版。
- 上位階層へ戻ったときに同じフィルタへ復元できる状態。
- 集計値から個人へ移る場合の権限確認と用途監査。

## 5 指標定義の原則

1. 得点は配点が異なる場合に単純平均せず、得点率または帳票定義の換算値を使う。
2. 偏差値は異なる母集団・定義を混在させず、MetricDefinitionIDを一致させる。
3. 回次比較は同一PersonIDかつ同一定義の科目だけを比較する。
4. 未受験・非掲載・解析不能を0点へ変換しない。
5. 集計結果には対象人数、除外人数、除外理由、データ更新日時を付ける。
6. 小人数群は設定値未満なら値を非表示にし、対象人数だけを表示する。初期推奨値は5だが会社承認で決定する。
7. 全国平均等の帳票値と、本システム内の塾生平均を別名で表示する。
8. 同一生徒の複数登録はACTIVEな最新版だけを通常分析へ含める。
9. 相関、同時変化、平均との差は因果関係として表示しない。
10. 指標ごとに比較可能性を判定し、定義版・配点・母集団が異なる場合は分離する。
11. 表示順位は価値判断ではなく、選択した指標の並べ替えであることを明示する。
12. 画面上の色だけで良否を伝えず、数値・ラベル・凡例を併記する。

フロントエンドのプロトタイプは、データ契約確定後に合成データで作る。最初に画面を固定すると、帳票から取れる情報や欠損状態をUI都合で失うため、Phase 1では情報構造と主要操作だけを先に確定する。

### 6.1 全チャート共通表示

- タイトルは「何の値か」「誰が対象か」「どの回次か」が分かる文言にする。
- 軸、単位、比較基準、母数、除外数、欠損数、更新日時を省略しない。
- ツールチップだけに重要情報を置かず、表形式でも同じ値を確認できるようにする。
- 分布には中央値と四分位を重ね、平均線だけで判断させない。
- 推移には比較可能者だけの線と、その人数を表示する。
- 小人数抑制時はグラフ要素を描画せず、理由と対象人数だけを表示する。
- 印刷・色覚差・狭い画面でも値を識別できる配色とラベルを使う。

## 7 将来の機械学習

### 7.1 候補タスク

- 次回模試の得点率・偏差値・判定の予測
- 成績上昇／低下リスクの分類
- 志望校ボーダー到達可能性の推定
- 分野・設問単位の次回重点候補

### 7.2 必須条件

- ML_IDはPersonIDからHMACで作る仮名IDとし、直接識別子を含めない。
- 学習時点より後の情報を特徴量へ入れない。
- 同一人物が学習用と評価用へ跨って漏えいしない分割を行う。
- 回次予測は時系列で分割し、未来データによるリークを防ぐ。
- 欠損理由を特徴として区別し、0埋めを既定にしない。
- ParserVersion、PayloadFormatVersion、ExportSchemaVersionを出力する。
- 予測値を成績正本へ書き戻さず、モデル版・生成日時付きの派生結果とする。
- 合否実績等を追加収集しない限り、「合格予測」を実績ラベルで学習できるとは表現しない。

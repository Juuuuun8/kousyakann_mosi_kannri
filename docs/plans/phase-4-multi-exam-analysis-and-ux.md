# Phase 4 複数模試分析・目的別UI 実装計画

- 基準仕様: `seiseki_system_spec_v1.docx` 6.5、6.6、7、8、10.2
- 承認済み変更: `SPEC-CHANGE-006`、`D-018`〜`D-023`
- 初期対象: 河合塾・全統共通テスト模試
- 本番接続: 会社承認まで禁止。合成データ、契約、GASコード準備だけを行う

## 1. 完了状態

1. 利用者は、どの模試・年度・回次・指標・校舎を見ているか常時確認できる。
2. 校舎・学校・生徒の比較に、受験科目の任意合算値を使用しない。
3. 共通テスト型、記述型、その他の模試を追加しても、既存Sheet列を模試ごとに増やさない。
4. 帳票に存在しない詳細分析を、0または欠損として誤表示しない。
5. 第1志望だけでなく、PDFから取れる全志望順位を扱う。
6. 文理・国公私区分を推定せず、それに依存しない分析を提供する。
7. 要確認条件は管理者設定とし、指導対象・原因・対応を自動決定しない。

## 2. Phase 4A: 比較可能性契約

### P4A-T01 指標選択の必須化

- Queryへ単一`SubjectDefinitionID`と単一`MetricDefinitionID`を必須指定する。
- 「全教科」をscalar比較指標として受理しない。
- 帳票掲載総合は独立SubjectDefinitionとして扱い、構成科目、満点、母集団、受験型を定義する。
- 異なる指標を並べる場合は個別系列として返し、平均・順位・変化量を合成しない。

受入試験:

- 科目未指定、複数指標無分離、任意合算要求を拒否する。
- 英数国総合と国理6-8型総合を同じ系列へ混ぜない。
- 未受験科目がある人の総合を、受験済み科目だけで再計算しない。

### P4A-T02 模試形式と回次

- `ExamDefinition`へProviderID、Format、Seriesを持たせる。
- `ExamEvent`へAcademicYear、Round、ExamDateを持たせる。
- 共通テスト型と記述型は既定で別系列とする。
- SchemaVersionが違っても、正規化済み科目と指標定義が一致する場合だけ比較候補にする。

境界例:

- 同じ「英語」でも、リーディング／リスニング／記述英語を暗黙統合しない。
- 偏差値は提供元や母集団が異なれば別MetricDefinitionとする。
- 得点率は問題難度が違うため、変化だけで成長・低下を断定しない。

### P4A-T03 CapabilityProfile

SchemaVersionごとに次をBooleanまたは詳細定義で管理する。

- subjectScores、deviation、ranks、trends
- domains、majorQuestions、answerMarks、blankMarks
- targets、targetSubjectBreakdown、convertedScores
- nationalAverage、schoolAverage、sameAbilityAverage

UI、分析API、ML出力は同じCapabilityProfileを参照する。非対応項目は`null`だけでなく`NOT_SUPPORTED_BY_REPORT`を返す。

## 3. Phase 4B: 本人照合

### P4B-T01 Person候補生成

- PDF内の氏名、かな、高校、学年、卒業見込年度、受験番号を候補生成に使用する。
- 受験番号はExamEvent内だけで有効とし、恒久IDにしない。
- 氏名単独一致、自動最高点一致、部分一致だけで確定しない。

### P4B-T02 管理者確認

- 候補なし: `NEW_PENDING`
- 単一候補でも未確認: `MATCH_PENDING`
- 管理者が既存Personへ接続: `RESOLVED`
- 管理者が新規Personを確定: `NEW_CONFIRMED`
- 複数候補、改姓、転校、同姓同名: `CONFLICT`

回次比較は`RESOLVED`または`NEW_CONFIRMED`だけを使う。照合操作、操作者、根拠、日時、差し戻しを監査する。

## 4. Phase 4C: 志望校正規化

### 階層

- UniversityID
- FacultyID
- ProgramID（学科・専攻・方式）
- AdmissionMethodID（日程、共通テスト利用、一般等）
- RawUniversity、RawFaculty、RawProgram、RawMethod

### 規則

- 原表記は正本として失わない。
- 正規化候補は自動提示しても、自信度だけで確定しない。
- 大学単位の人数集計は可能だが、判定・ボーダー比較はProgram／AdmissionMethodを分離する。
- 改組・名称変更・同名学部は有効期間付き別IDとする。
- 未正規化行は「未整理」として残し、他模試の志望先へ結合しない。

### 分析

- 志望順位別A〜E構成
- 第1〜第3志望のいずれかが指定判定帯にある人数
- 指定順位がすべて指定判定帯の人数
- 同一正規化志望先の判定・ボーダー差推移
- 志望変更は旧・新ProgramIDを並べ、優劣や理由を推定しない

## 5. Phase 4D: 目的別UI

### 状況をつかむ

- 選択指標の人数、中央値、四分位、分布
- 同一Person・同一模試形式・同一指標の推移
- 帳票掲載の科目・総合指標一覧
- 登録確認中、比較不能、非対応項目の件数

### 集団を比べる

- 校舎・高校の箱ひげ表示と個人ドット分布
- 校舎×分野マトリクス
- 全国差、同学力帯差、無回答率を別指標として表示
- 科目→分野→大問→設問→個人のドリルダウン
- 四分位範囲だけで二極化と表現しない

### 生徒を探す

- 氏名、校舎、高校、全志望校の検索
- 指標偏差値、同一指標前回差、志望判定、確認条件で絞込・並替
- 個人カルテは模試形式別に推移を分離
- Person照合状態を表示し、未確定者の回次推移を作らない

### 志望校を確かめる

- 全志望順位の判定構成
- 正規化した大学・学部・方式別の人数、判定、ボーダー差
- 同一志望先の回次推移
- 未正規化件数と管理者確認導線

### 管理機能

登録・取込状況、本人照合、志望校マスタ、確認条件、ML出力を分析ナビゲーションから分離する。

## 6. Phase 4E: 要確認条件

- RuleID、RuleVersion、Label、Enabled、MetricDefinitionID、Operator、Threshold、MinimumEventsを持つ。
- 初期例は「同一指標の前回比が-5pt以下」「第1〜第3志望がすべてE判定」だが、会社運用値として承認するまでデモ設定と明記する。
- 該当理由、使用値、比較回、比較可能性を返す。
- 「危険」「指導すべき」「原因」といった断定語をルール名にしない。
- ルール変更後も過去の表示を再現できるようRuleVersionを監査へ残す。

## 7. Phase 4F: 新模試スキーム分析手順

1. 個人情報を除いた許可済み帳票または安全な閲覧環境を用意する。
2. ページ、固定見出し、座標、繰返しブロック、任意欄を棚卸しする。
3. 印字項目を`raw-field-inventory`へ列挙し、型、単位、範囲、欠損条件、根拠ページを記録する。
4. 既存Subject／Metric／Target masterへ対応付け、推定が必要なものは未解決にする。
5. SchemaVersion manifestへdetect marker、CapabilityProfile、validation、normalization mapを記録する。
6. Parserのdetect、extract、validate、normalizeを別関数で実装する。
7. 正常、ページ欠落、順序変更、未知ラベル、空欄、画像PDF、重複、訂正版をfixture testする。
8. 実帳票で件数・構造だけをdry-runし、保存前に人が承認する。
9. 既存SchemaVersionの回帰試験を通す。
10. 対応開始日時、承認者、ParserVersion、SchemaVersionを記録して有効化する。

この手順の成果物形式を固定した後に、AI用スキルとしてパッケージ化する。スキルは未知項目を推定確定せず、未解決一覧と必要な人間判断を返す。

## 8. Feedback gate

### 講師・社員レビュー

- 4分類から目的の画面へ迷わず移動できるか。
- 現在の模試、回次、指標を誤認しないか。
- 校舎差、分野差、生徒一覧、併願構成から必要な事実へ到達できるか。完了可否・操作数・時間・誤読を実測し、根拠なく「3操作以内」などの合格基準を固定しない。
- 用語が大学受験現場で誤解を招かないか。

### 帳票担当レビュー

- 取得可能／非対応／欠損の分類が正しいか。
- 新回・改訂帳票を受領してから、SchemaVersion追加までの手順が再現可能か。

### 情報管理レビュー

- 個人情報が許可済みSheets以外に永続化されないか。
- 本人照合、志望校正規化、確認条件変更、ML出力が監査されるか。

Feedbackは指摘、根拠、重要度、採否、対応task、再確認者を記録する。口頭指摘だけで仕様を変更しない。

## 9. Release gate

- 単体・契約・回帰・アクセシビリティ・狭幅表示が合格している。
- 合成デモに実在個人情報が含まれない。
- 全教科任意合算と第1志望限定集計が残っていない。
- 未対応帳票をREADYにしない。
- 会社承認前は実Sheets、GAS本番、Secret、実PDFへ接続しない。

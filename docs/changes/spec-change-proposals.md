# 仕様変更提案

## 運用

技術仕様書v1.0と、その後に承認された最上位制約が衝突する場合に使用する。承認前にコードへ反映せず、承認後は仕様書次版、トレーサビリティ、フェーズ計画、テストへ反映する。

## SPEC-CHANGE-001 ML用出力の保存先

| 項目 | 内容 |
|---|---|
| 状態 | 方針承認済み 仕様書改訂待ち |
| 対象 | 仕様書6.7 ML用CSV出力 |
| 新しい制約 | 個人情報は職場PC Googleアカウント所有のGoogle Drive上のGoogle Sheets以外へ保存しない |
| 問題 | CSVをブラウザへ返すと、利用者PCのダウンロード領域へ仮名化された成績情報が保存される可能性がある |
| 初期方針 | GASが職場PCアカウント所有の専用ML用Google Sheetを生成または更新する |
| 維持する機能 | 対象期間・項目指定、直接識別子除外、ML_ID付与、監査ログ |
| 無効化する機能 | 会社承認前のCSV自動ダウンロード |
| 将来 | ML実行環境と保存境界が承認された時点で、CSVまたはAPI出力を再審査する |

### 必須テスト

- ML出力に氏名・メール等が含まれない。
- 出力先が所定のGoogle Sheetである。
- ブラウザが識別可能ファイルを自動ダウンロードしない。
- 出力操作が監査される。
- INPUTには実行権限がない。

## SPEC-CHANGE-002 OTP・セッションの短期保存先

| 項目 | 内容 |
|---|---|
| 状態 | 方針承認済み 仕様書改訂待ち |
| 対象 | 仕様書6.1、6.2、9.2のOTP・セッション短期ストア |
| 新しい制約 | 利用者と結び付く個人情報をGoogle Sheets以外へ保存しない |
| 問題 | CacheServiceへメール、UserID、OTP状態、セッション対応を置くと、Google Sheets以外の保存となる |
| 初期方針 | 非共有システム台帳内のOtpChallenges、Sessionsシートへ、有効期限付きで保存する |
| セキュリティ | OTPとセッションIDは平文保存せずハッシュ化し、失敗回数、期限、失効状態を保持する |
| CacheService | 利用者と結び付かないnonce等に限定する |
| 清掃 | 時間主導トリガーと各API呼出し時の遅延清掃で期限切れ行を削除する |
| 影響 | Sheetsアクセス回数と競合が増えるため、Phase 1以降で負荷試験する |

### 必須テスト

- CacheServiceにActor、Email、UserID、OTP、SessionID対応が保存されない。
- OTPとセッションIDが平文保存されない。
- 期限切れ、REVOKED、ログアウト後のセッションが拒否される。
- 同時更新時にLockServiceで競合を防ぐ。
- 清掃失敗が認証成功に化けない。

## SPEC-CHANGE-003 仕様書原本の管理

| 項目 | 内容 |
|---|---|
| 状態 | 暫定 |
| 問題 | リポジトリの公開範囲が確認できない状態で社内仕様書本体をコミットできない |
| 初期方針 | 原本は承認済みの社内保管場所に置き、GitHubには要件IDと非機密の計画書だけを置く |
| Lunaへの提供 | 各タスクに該当章、要件ID、必要な原文抜粋または参照可能な原本パスを含める |
| 将来 | 会社承認済みの非公開Organization repositoryが用意された場合に、仕様書格納可否を再判断する |
